# 2026-10-25 公开源码同步

本次将当前早苗源码按文件白名单同步到公开仓库，补齐 9 月 17 日之后的功能和离线回归。
公开副本使用可配置路径和合成测试身份；生产配置、聊天、记忆、素材及服务端数据不随源码发布。

## 本次能力

- **对话与记忆**：连续短消息合并、更正替换、旧回复取消；个人记忆按群和用户隔离，支持来源追溯和 `!记忆`、`!记住`、`!忘记`。撤回、忘记与关闭话题会使相关待完成回复失效。
- **回复与角色**：当前角色名为八千代，保留早苗称呼；倾听偏好、事件跟进、表达经验和回复教训按对应作用域应用。贴纸与回复学习以实际送达记录为依据，默认移除 AI/费用页脚，只处理气泡末尾的中文句号。
- **模型与媒体**：DeepSeek 流式输出与工具适配、Gemini 签名工具结果和最终答复处理、可配置的 OpenAI 兼容适配、网页来源分段、当前群内的引用/转发读取，以及默认关闭的静默图片观察。
- **群服与运维**：多群路由上下文、群默认服务器、只读状态节点、独立群回执，以及 Windows/POSIX 远程日志。补充显式配置的备份和 MSLX 控制适配、店铺监控快照读取。
- **网络诊断**：`!ping` 和 `!ping full` 使用固定参考节点、时间上限和冷却；当前探测实现依赖 Windows 的 `ping.exe` / `curl.exe`，不接受任意测速地址。来源和许可证见 [上游说明](../UPSTREAM-NOTICE.md)。

## 配置变化

复制 [环境示例](../examples/env.example.ps1) 到仓库根目录的 `env.ps1` 后再填写本机值。
示例中的服务器注册表路径已修正为同目录 `servers.json`。

| 配置 | 用途 |
| --- | --- |
| `SANAE_QQ` / `SANAE_BOT_QQ` | 当前机器人账号；前者优先。未配置时为 `0`，部署时必须填写自己的账号。 |
| `SANAE_HISTORICAL_BOT_QQ` | 逗号分隔的旧机器人账号，用于排除自我学习；默认无私有历史账号。 |
| `SANAE_GROUPS` / `SANAE_RELAY_GROUPS` | 允许处理消息的群 / 允许群消息转服的群；逗号分隔。 |
| `SANAE_DISABLED_GROUPS` | 暂停处理的群，逗号分隔。 |
| `SCE_SERVER_GROUP_DEFAULTS` | `群号:服务器id,另一群号:另一服务器id`，不跨群借用默认目标。 |
| `SCE_SERVER_EXTRA_REGISTRY` | 可选附加注册表；所有启用条目的 `id` 和 `prefix` 必须唯一。 |
| `LLBOT_API_TOKEN` / `LLBOT_CALLBACK_TOKEN` | OneBot 请求与上报鉴权；只放在本机私有配置中。 |
| `SANAE_MENTION_ONLY` / `SANAE_NAME_CALL_ENABLED` | 默认 `1` / `0`，优先使用明确 @；按部署需求调整。 |
| `CONVERSATION_MEMORY_PATH` / `EXPRESSION_MEMORY_PATH` / `REPLY_LESSONS_PATH` | 私有状态文件，默认位于 `state/`，不得提交。 |
| `SANAE_SILENT_VISION` | 默认 `0`；设为 `1` 后使用已配置视觉模型，可能产生 API 费用。观察只留在短期内存，每条最多 2 图，最长 15 分钟，不自行发送消息。 |
| `STICKER_MANIFEST` | 本地贴纸清单；素材自行提供。 |

文本 provider 为 `deepseek`、`gemini` 或 `gpt6luna`。后者是本项目的 OpenAI 兼容适配名称，
使用 `GPT6LUNA_BASE_URL`、`GPT6LUNA_MODEL` 和私有 `gpt6luna_api_key`，模型标识由所用服务决定。
视觉 provider 使用 `SANAE_VISION_PROVIDER=zhipu` 或 `deepseek`。公开版继续保留费用估算边界：
未配置可靠费率的 provider 不套用 DeepSeek 的价格。

注册表条目可增加 `remote_ssh_host`、`remote_server_dir`、`remote_os`、`remote_python`，
读取已配置 SSH 主机上的服务器日志；需预先配置 SSH 别名、密钥和受信的 known_hosts，
这些配置留在部署机器上。
`kind: "status"` 的条目只用 `host` / `port` 查询 Java 服务状态，不提供 RCON；
`chat_enabled: false` 可排除该条目的群服聊天转发。

可选服务适配：

- `SANAE_LEGACY_BACKUP_PIPELINE` 指向提供 `--status` / `--manual` 接口的外部备份脚本，解释器由 `SANAE_LEGACY_BACKUP_PYTHON` 指定；未配置时停用。
- `SANAE_MSLX_CONTROL_SCRIPT` 指向部署者自己的控制脚本；未配置时停用。`SANAE_MSLX_POWERSHELL` 默认 `powershell.exe`。
- `SANAE_BACKUP_LOCAL_DIR` 与 `SANAE_BACKUP_NAS_DIR` 指定本地备份源和副本目录。`SANAE_BACKUP_KEEP_COMPLETE` 默认 `0`，不轮换删除；只有显式正数才轮换符合条件的已验证副本。
- `LEGACY_MONITOR_GROUPS` 为逗号分隔的监控通知群，各群单独记录送达结果。
- `SANAE_SHOP_MONITOR_ROOT` 指向含 `config.json`、`state/monitor.json` 的店铺监控目录，默认仓库下 `shop-monitor/`；本仓库提供读取入口，不包含外部监控服务。

备份脚本状态接口返回 JSON，含 `enabled`、`state`；手动执行成功时返回
`state: "complete"`、`bytes`，可带 `archive`，退出码为 `0`。忙碌时退出码 `3`，
标准输出返回 `state: "busy"`；其他失败从标准错误读取含 `state` / `message` 的 JSON。
MSLX 控制脚本需接受 `-Target Legacy -Action restart|stop -ApprovalReference ...
-ApprovePlayerImpact -NoticeSeconds 60 -TimeoutSeconds 900 -Confirm:$false`；
该适配对应怀旧服的已确认操作，不是通用主机控制器。

环境示例显式关闭 `SANAE_ENABLE_BACKUP_WATCH`、`SANAE_ENABLE_NAST_SYNC` 和
`SANAE_ENABLE_LEGACY_MONITOR`，按需启用。代码为兼容旧部署保留前两项未设置时的默认 `1`；
事件监控未设置时为 `0`。外部运维脚本、旧 NAST 服务和生产部署文件不随本次同步打包。

## 验证边界

运行 `python scripts/test-offline.py`，或在其后指定 `test_模块名` 运行受影响范围。
每个测试模块独立进程并使用临时状态，阻断外部 socket 连接；HTTP 隔离测试仅允许其自己
注册的随机回环端口，不允许访问真实 OneBot、Minecraft 或模型服务。
结果和失败日志保存在忽略的 `build/offline-tests/`。

GitHub Actions 覆盖 Windows / Ubuntu × Python 3.11 / 3.12。
本地 Python 3.12 验证共 70 个模块、942 项通过，0 失败、0 错误、0 跳过；
其中原摘要测试的旧 token 预算断言已按当前独立摘要预算更新并单独复验。
跨平台 CI 还修正了 Python 3.11 的贴纸路径语法、Linux 下的媒体路径测试夹具，
并为周报文件锁补齐 POSIX 互斥与异常释放验证。Windows 专属的远程读取测试在 Ubuntu 跳过。
本次是源码同步与离线验证，不代表重新完成真实 QQ、模型接口或生产端到端验收。
